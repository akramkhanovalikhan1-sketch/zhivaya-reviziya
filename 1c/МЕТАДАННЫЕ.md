# Метаданные 1С:Розница — объекты «Живая ревизия»

Создаёт Айдын в конфигураторе. Имена регистров и полей должны совпадать с `Module.bsl`.

## 1. Регистр сведений `ИсторияСканированияТСД`

Периодичность: **независимый, с периодичностью по позиции регистра** (период с миллисекундами — измерение `Период` типа Дата, запись через `ТекущаяУниверсальнаяДатаВМиллисекундах` недоступна как Дата; использовать измерение `Момент` типа Строка 36 / УникальныйИдентификатор **или** Дата + измерение `ИдЗаписи`).

Практичная схема (чтобы не упереться в секундную коллизию 10 ТСД):

| Роль | Имя | Тип |
|---|---|---|
| Измерение | МоментВремени | Дата (дата + время) |
| Измерение | ИдЗаписи | УникальныйИдентификатор |
| Измерение | ИдентификаторТСД | Строка 20 |
| Измерение | Сотрудник | СправочникСсылка.ФизическиеЛица |
| Измерение | НомерЗоны | Строка 20 |
| Измерение | НомерСессии | Число 5,0 |
| Измерение | Номенклатура | СправочникСсылка.Номенклатура |
| Ресурс | Количество | Число 15,3 |
| Реквизит | СчитанныйШтрихкод | Строка 48 |

Индекс: `НомерЗоны + НомерСессии + Номенклатура`.

## 2. Регистр сведений `СессииЗонРевизии` (технический)

Независимый, **непериодический**. Одна актуальная запись на зону.

| Роль | Имя | Тип |
|---|---|---|
| Измерение | НомерЗоны | Строка 20 |
| Ресурс | НомерСессии | Число 5,0 |
| Ресурс | Сотрудник | СправочникСсылка.ФизическиеЛица |
| Ресурс | ВремяСтарта | Дата (дата + время) |
| Ресурс | ВремяФиниша | Дата (дата + время) |
| Ресурс | Статус | ПеречислениеСсылка.СтатусыЗонРевизии |
| Ресурс | ЗаблокированныйСотрудник | СправочникСсылка.ФизическиеЛица |

Историю сессий (для отчёта Иванов vs Сидоров) дублировать в регистр `ИсторияСессийЗонРевизии` при каждом Start/Finish — не затирая прошлые номера сессий.

## 3. Перечисление `СтатусыЗонРевизии`

- `Свободна` (серый)
- `ВРаботе` (жёлтый)
- `Закрыта` (зелёный)
- `Перепроверка` (оранжевый)

## 4. Регистр сведений `ГруппыАналоговНоменклатуры`

| Роль | Имя | Тип |
|---|---|---|
| Измерение | Номенклатура | СправочникСсылка.Номенклатура |
| Ресурс | ОсновнаяНоменклатура | СправочникСсылка.Номенклатура |

Заполняется товароведом / обработкой «схлопывание по схожести наименований».

## 5. HTTP-сервис `ТСДРевизия`

- Корневой URL: `tsd`
- Повторное использование сеансов: **да** (критично для < 0.1 сек)
- Шаблоны: `auth`, `startZone`, `scanItem`, `finishZone` — метод POST, обработчики в `Module.bsl`

## 6. Обработка `АРМРуководителяРевизии`

Форма: цветовая матрица зон + таблица

`Товар | План 1С | Факт ТСД | Продано после Старта | Итоговый факт | Отклонение`

Формула: **Итоговый факт = Количество по ТСД (актуальная сессия) + продажи ККМ после ВремяСтартаЗоны**.

Кнопка «Сформировать финальные акты» — `Доступность = (все зоны.Статус = Закрыта)`.

Кнопка «Направить на перепроверку»: статус → Перепроверка, `ЗаблокированныйСотрудник` = сотрудник закрытой сессии.

## 7. Алгоритмы (порядок внедрения)

1. Временной сдвиг кассовых чеков относительно `СессииЗонРевизии.ВремяСтарта`.
2. Скользящее окно: закрытая зона — продажи после финиша тоже плюсуются к факту ТСД до конца всей ревизии.
3. Автозачет пересортицы: одна группа, одна цена, зеркальные отклонение → встречные акты.
4. Полуавтомат: разная цена → вкладка «Кандидаты на пересортицу».
5. РЦ: непроведённые перемещения 5 дней; «вырезать» приход, если ни одна позиция накладной не встречена ТСД.
6. Cut-off: карантинная зона, документы после завершения ревизии.
7. Отчёт «Сравнение первичного и повторного подсчета».

Имя регистра штрихкодов в Рознице уточнить по релизу (`Штрихкоды` / `ШтрихкодыНоменклатуры`). Поиск сотрудника по бейджу — заменить заглушку в `НайтиСотрудникаПоБейджу`.
