# Этап 3 — старт для Айдына

Конфигуратор 1С сам файлы не подхватит. Код уже в GitHub. Ваша работа — создать объекты и вставить модули.

Репозиторий (клонировать, не копировать архив):

```
git clone https://github.com/akramkhanovalikhan1-sketch/zhivaya-reviziya.git
git pull
```

Агент из чата конфигуратор не откроет. Этап закрыт, когда с любой машины:

```
GET http://{сервер}/{база}/hs/tsd/ping
```

вернёт `{"ok": true, "service": "zhivaya-reviziya-1c", ...}`.

## Порядок в конфигураторе

1. Перечисление `СтатусыЗонРевизии`: Свободна, ВРаботе, Закрыта, Перепроверка.
2. Регистры из `1c/МЕТАДАННЫЕ.md` — имена полей один в один:
   - `ИсторияСканированияТСД`
   - `СессииЗонРевизии` (есть ресурс **Карантин**)
   - `ИсторияСессийЗонРевизии`
   - `ЗаморозкаНоменклатурыРевизии`
   - `ГруппыАналоговНоменклатуры`
3. Общие модули (сервер, вызов сервера):
   - `РасчетИтоговРевизии` ← `1c/ОбщиеМодули/РасчетИтоговРевизии.bsl`
   - `АРМРевизии` ← `1c/ОбщиеМодули/АРМРевизии.bsl`
4. HTTP-сервис `ТСДРевизия`, корневой URL `tsd`, повтор сеансов = **да**.
   Шаблоны: `1c/HTTPСервисы/ТСДРевизия/ШАБЛОНЫ.md` (на каждый ещё OPTIONS → `CORSOPTIONS`).
   Модуль целиком: `1c/HTTPСервисы/ТСДРевизия/Module.bsl`.
5. Публикация на веб-сервере. Проверка `ping`.
6. Заглушки (после того как ping зелёный):
   - `НайтиСотрудникаПоБейджу` — ваш бейдж в Рознице
   - `НайтиНоменклатуруПоШтрихкоду` — уже пробует оба регистра
   - `НоменклатураЗаморозкиЗоны` — паллеты P-01 / P-02
   - `ПродажиККМПосле` — если нет `ЧекККМ.Архивный`, уберите условие
7. Форма обработки `АРМРуководителяРевизии` — матрица зон из `АРМРевизии.ДанныеМонитора()`, кнопка актов `АРМРевизии.СформироватьАкты()`.

Подробный чеклист: `1c/ЧЕКЛИСТ_АЙДЫНА.md`.

Прислать в чат: URL `ping` и текст ответа. Тогда этап 3 закрываем и берём стыковку ТСД.
