## Что уже в коде

- ТСД: бейдж → зона → скан → **итог зоны**; очередь оффлайн; undo; confirm перепроверки; зоны с сервера.
- Mock: ККМ, Q-RC, паллеты, автозачет, `closeIdle`, финальные акты, сброс демо.
- 1С-заготовки: `1c/HTTPСервисы/ТСДРевизия/Module.bsl`, `АРМРевизии`, `РасчетИтоговРевизии`.
- Контракт: `docs/openapi.yaml`. Прогон зала: `docs/ТСД_ЗАЛ.md`. Чеклист: `1c/ЧЕКЛИСТ_АЙДЫНА.md`.

## Дыры 1С относительно mock

Есть в 1С-модуле: auth, startZone, scanItem, finishZone, ping, zones, sessionLines, undoLast, dashboard, closeIdle, recheck, CORS OPTIONS.

Нет в 1С-модуле (в mock есть): `arm/finalize`, `arm/sale`, `arm/applyOffset`, `arm/postTransit`. Для актов и формулы товароведу это нужно. `info` и `arm/reset` — только удобство демо.

Формы обработки `АРМРуководителяРевизии` в репозитории нет — только серверные процедуры. Матрицу зон Айдын рисует в конфигураторе.

Заглушки, без которых живые бейджи/товары не найдутся: `НайтиСотрудникаПоБейджу`, `НайтиНоменклатуруПоШтрихкоду`, `НоменклатураЗаморозкиЗоны`, условие `ЧекККМ.Архивный`.

## Критерий финала

- `ping` живой 1С отвечает `ok`.
- Реальный бейдж и товар с полки проходят без демо-кодов.
- Итоговый факт = факт ТСД + продажи ККМ после секунды старта зоны.
- Q-RC не стартует. Все рабочие зоны закрыты. Акты появились в базе.
